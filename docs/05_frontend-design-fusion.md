# 1.3.0 规划：融合 frontend-design 的设计方法

状态：已实现（1.3.0） · 日期：2026-11-03 · 来源：用户提供的 frontend-design 技能（作者 zxh），以下简称 FD。

## 1. 可借鉴之处与取舍

| FD 的做法 | 对 design-to-dev 的价值 | 采用方式 |
|---|---|---|
| 写代码前先锁定方向：用途、受众、调性、记忆点，并写明展示字体、正文字体、主色、强调色 | 1.2 只让设计师选“方向”，没有落到具体的字体、颜色和记忆点 | 新增“设计方向说明”：理解卡里写明，HANDOFF 新增一节 |
| 9 种审美方向，每种有关键词和适用场景 | 1.2 只有 3 种 | 3 种快速选项保留，另附 9 种完整菜单供设计师挑 |
| 四大支柱：独特字体、主色加锐利强调色、编排动效、构图 | 1.2 有规则、无方法；字体全用系统字，最显“模板味” | 写进视觉方向参考；字体改为真实字体文件打包进原型 |
| 禁止默认审美（系统字体作展示字、白底紫渐变、三卡片首屏） | 正好对应用户说的“没档次” | 列为“去 AI 味”清单，并入视觉自查 |
| 氛围层：渐变网格、噪点颗粒、几何纹理 | 让页面不再是平涂色块 | 只用离线可用的做法（内联 SVG 噪点、径向渐变、细线），必须与方向一致 |
| 一次编排好的入场序列（3–6 组，间隔 60–120ms），尊重减少动效设置 | 原型首屏更有质感 | proto-kit 增加入场编排的约定与样式 |
| 基准数值（大标题 ≥48px、字距 −0.02 ~ −0.04em、中文行长 28–40 字、三级阴影 2/8/24px、动效时长三档） | 可直接检查 | 写入基准表；能机检的写进检查脚本 |
| “每次产出都不同，不要趋同” | 模板默认样式容易导致所有原型一个样 | 模板只是起点，方向说明必须针对具体产品 |

不采用或改造：

- FD 要求“直接产出生产级代码、不留占位”。我们的产物是原型，占位是有意的，并按【待定】标注。这一条保持不变。
- FD 偏向营销页的戏剧化构图（非对称、破格）。应用界面以可用性优先：大胆构图只用在页头、空状态、首屏和品牌时刻，列表和表单仍保持规整。
- 有设计稿或 VI 时，还原度优先；FD 的创作方法只用在没有设计稿的部分。

## 2. 决策

| ID | 决策 |
|---|---|
| X-D1 | 新增 `scripts/fetch_fonts.py`：从原型文件收集实际用到的字符，用 Google Fonts 的 `text=` 子集接口下载 woff2 到 `prototype/fonts/`，生成 `fonts/fonts.css`。原型仍可离线运行；没有网络时回退到系统字体，并把字体记为【待定】。 |
| X-D2 | 视觉方向参考改写为“方法 + 标准”：设计方向说明、9 种方向菜单、四大支柱、氛围做法、入场编排、基准数值、去 AI 味清单。12 项自查并入其中。 |
| X-D3 | 审计 R-6 的根因（自查全靠自评）：`check_output.py` 增加客观视觉检查，包括 12px 以下字号、非 4px 刻度的间距、字重种数、有动画时是否处理减少动效、展示字体是否只有系统字体。它们作为警告输出，收尾时必须修正或说明。 |
| X-D4 | Readlog 用 FD 方法重做：写方向说明；打包品牌字体 Noto Serif SC 与正文字体子集；加纸张颗粒氛围和入场编排；同时修掉审计 R-5、R-6、R-7、R-9、R-10、R-11。 |
| X-D5 | 实测登录页用 Geist 字体（原稿所用的开源字体）重跑，验证字体打包对还原度的作用。 |
| X-D6 | 版本 1.3.0；CHANGELOG 与 README 注明借鉴 frontend-design（zxh）。 |

M1：参考改写、fetch_fonts、检查脚本视觉检查、模板调整 → M2：Readlog 重做、登录页重跑 → M3：auditor 正式审计、evolver 记台账、交用户评审。

## 5. 结果

- X-V1：子集字体在 file:// 下加载成功（`document.fonts` 三个字体均为 loaded，`document.fonts.check` 为 true）。

- 视觉自查 A 在 Readlog 上 0 条警告；在实测产物上发现 1 条（10px 的装饰性首字母），说明检查有效。
