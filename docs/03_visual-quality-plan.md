# 1.2.0 视觉质量规划

状态：规划 · 日期：2026-11-03

## 1. 理解卡

- **触发**：用户评价示例与模板“太丑、没有美感、审美不够档次”。证据：Readlog 截图里，宋体回退字体粗糙；卡片里套卡片；按钮是整块的重色；封面只是单色块加一个字；琥珀色圆圈表示连续打卡；整体像未经设计的后台模板。
- **根因**：1.x 只规定“能用”（token 化、状态、对比度），没有任何审美标准；没有视觉稿时，Agent 只能套用功能性的默认样式。intake 也不会主动索取 VI 和视觉参考。
- **目标**：技能在任何输入下都能给出达到“现代精致极简”水准的原型。有 VI 或参考时以它们为准；没有时由设计师选择审美方向，并按方向预设与审美标准执行，交付前做视觉自查。
- **非目标**：不做品牌设计、不生成插画或图标库；不引入外部字体与 CDN（原型仍须在 file:// 下离线运行）。

## 2. 规划契约

- `done_definition`：新增 `references/visual-direction.md`（审美原则、三个方向预设、视觉自查清单）；intake 加入 VI 与视觉参考的索取和方向选择；默认模板（tokens.css、styles.css、pages.js 示例）按“现代精致极简”重做；Readlog 按新方向重做；用一份高水准公开登录页重新实测并按结果迭代；发布前正式调用 auditor 并出报告；版本 1.2.0。
- `validation_method`：在相同视口下，把 Readlog 新旧截图并排对比；把实测原型截图和原图并排对比；按视觉自查清单逐项打分并写入实测记录；check_output、单元测试、浏览器测试、build --check 全部通过。
- `fail_condition`：新模板在 file:// 下需要外部资源才能达到效果；或自查清单无法落成可判断的条目（只剩“要好看”这种空话）。

## 3. 决策

| ID | 决策 | 理由 |
|---|---|---|
| V-D1 | 技能第 1 步的提问改为：先要 VI 规范（色彩、字体、标志）和 2–3 张视觉参考（喜欢的产品或截图）；都没有时，让设计师在三个方向里选：现代精致极简（默认）、编辑杂志感、温暖手作感。仍保持一轮最多 5 个问题。 | 审美方向是设计师的决定，不能由 Agent 猜。 |
| V-D2 | 新增 `references/visual-direction.md`：可检查的审美原则、三个方向的 token 预设、视觉自查清单。 | 把“好看”落成可执行、可检查的条目。 |
| V-D3 | 默认模板改为“现代精致极简”：中性灰阶加一个强调色；系统无衬线字体栈；14–16px 正文和紧凑字号阶梯，大标题字距收紧；1px 细边框为主、阴影很轻；圆角 6/10/14；控件高 40px；150ms 微动效。 | 用户选定的方向；不依赖外部字体也能做出精致感。 |
| V-D4 | 视觉自查是第 6 步的必做项：截图后逐条核对清单，不达标就改；结果写进收尾。 | 审美不能只靠规则文字；没有自查就会回到“能用就行”。 |
| V-D5 | Readlog 重做：保留品牌的【确定】项（Moss、Ink、Paper、标题衬线、手机通栏主按钮），用精致极简的手法重新组织层级、封面、连续打卡、分栏和表单。 | 示例是仓库门面，要证明有品牌约束时也能做出质感。 |
| V-D6 | 实测稿件换成设计水准高的公开登录页（候选：Linear、Vercel，按能否获取决定），品牌名与标志仍替换为占位，产物不入库。 | 用户要求；验证技能能否还原高水准设计。 |

## 4. 假设

- A-1 没有字体文件时，系统无衬线字体栈（SF Pro / Segoe UI / PingFang SC）足以呈现精致感；品牌字体仍按原规则记为【待定】。
- A-2 三个方向预设只是起点；有 VI 或参考时，以它们为准，覆盖预设。
