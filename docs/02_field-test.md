# 实测记录：真实设计稿

日期：2026-11-02 · 技能版本：1.0.0 → 1.1.0

## 稿件

- 来源：GitHub 公开登录页 `https://github.com/login`，用 Playwright 以 390×844、2 倍像素、浅色模式截图（780×1688 px），作为“设计师给的一张手机截图”输入。
- 同时尝试截取找回密码页，被站点的反自动化页面拦截，按站点意愿不重试；于是这次实测正好是常见情形：**只有一张图，图上有多个链接指向没有设计的页面**。
- 版权与品牌：第三方截图和实测产物只保存在会话临时目录，不提交入库。原型中的品牌名和标志替换为 “Acme” 占位，避免做出仿冒的登录页。

## 过程

按 1.0.0 的 SKILL.md 逐步执行：一轮问题（采用默认：只做登录页、核心流程为登录、手机、模式 A）→ tokens → 原型 → 标注 → HANDOFF → `check_output.py` → 浏览器走查并与原图并排对比。

结果：检查脚本最终通过；浏览器中空字段校验、错误凭证横幅、正确凭证到达结束页、超范围链接提示均可用，无控制台报错；与原图并排对比，颜色、结构、控件尺寸一致。

## 发现

| # | 现象（证据） | 原因 | 1.1.0 的改动 |
| --- | --- | --- | --- |
| F1 | 技能只说“截图上的值是估计值”。实际对图片做颜色直方图，一次就得到精确色板（#1f883d、#0969da、#1f2328、#59636e、#d1d9e0、#f6f8fa）；也没有提示 780 px 宽是 2 倍图，尺寸要除以 2。 | 缺少取色与倍率方法。 | 新增 `scripts/palette.py`（标准库解码 PNG：主色直方图、指定点取色、倍率提示）；intake 与 tokens 参考加入取色、倍率步骤；设计师自己的定稿上取到的颜色可记为【确定】。 |
| F2 | 手写的对比度两次出错：示例中 5.0/5.6（实为 4.96/5.47），实测中 4.6/5.9（实为 4.52/5.74）。 | 对比度靠心算。 | `palette.py --contrast` 计算 WCAG 对比度；HANDOFF 中的对比度必须来自脚本输出。 |
| F3 | 核心流程“登录成功之后”去哪，设计里没有；技能同时要求“流程走通”和“不做没要求的页面”，两条规则冲突。图上 5 个链接指向没设计的页面，也没有处理方式。 | 缺少流程边界的规则。 | 允许为流程终点做一个“桩页面”，标【待定】并列入页面清单；超范围链接加 `data-out`，由 proto-kit 统一弹出“不在本原型范围”提示，并列入待定问题。 |
| F4 | 标志、第三方登录图标无法从截图取得，模板也没有素材清单。 | 缺少素材处理规则。 | 素材用占位并标【待定】；HANDOFF 模板第 3 节增加“素材清单”。输入是他人产品（参考图、竞品）时，不复刻其品牌名与标志。 |
| F5 | 登录类流程需要测试账号，否则开发和评审不知道怎么走通。 | 缺少演示数据说明。 | 原型参考要求：演示账号写在 HANDOFF 第 0 节；原型不得发送任何输入到网络。 |
| F6 | 把从截图量出的“标题常规字重”标成了【确定】，并排对比发现原图是半粗。 | 标注规则只对 tokens 写明了“测量值记为示意”，对元素标注没有写。 | 标注参考明确：从截图测量的视觉属性在元素标注中也只能是【示意】，【确定】需要权威来源或设计师确认。 |
| F7 | 模板按钮默认粗体，原图的第三方登录按钮是常规字重；模板样式悄悄覆盖了设计。 | 复制模板后没有要求对照原图调整基础组件。 | 第 3 步要求复制模板后按设计调整基础组件；第 6 步要求在同一宽度下把原型截图与原图并排对比。 |
