# Design tokens

## What to extract

The names below are the ones `templates/tokens.css` provides; most are read by `templates/styles.css`, the rest are ready for your pages. Keep them (change values, not names) so the template styles keep working; add new names for anything extra.

| Group | Tokens the template provides | Notes |
| --- | --- | --- |
| color, neutrals | `page` (page background), `surface` (cards, inputs), `surface-sunken`, `border`, `border-strong`, `text`, `text-secondary`, `text-tertiary` | Three text colors at most. |
| color, actions | `primary`, `primary-hover`, `primary-active`, `on-primary`, `accent`, `accent-soft`, `focus-ring` | One accent. Derive hover/active by shifting lightness 6–10% when the design does not show them; mark derived ones Indicative. |
| color, feedback | `success`, `success-soft`, `warning`, `warning-soft`, `danger`, `danger-soft`, `info`, `disabled-bg`, `disabled-text` | |
| font | `font-family-base`, `font-family-display`, `font-weight-regular`, `-medium`, `-semibold` | Use a system stack fallback after every family. |
| type scale | `font-size-xs` … `font-size-3xl`, `line-height-tight`, `line-height-base`, `letter-spacing-tight`, `letter-spacing-wide` | Snap screenshot measurements to the nearest step of a consistent scale (e.g. 12/13/14/16/20/24/32). |
| space | `space-1` … `space-12` on a 4px base | Measure padding and gaps; snap to the base. |
| radius | `radius-sm`, `-md`, `-lg`, `-xl`, `-full` | |
| shadow | `shadow-xs`, `-sm`, `-md` | Write as full CSS shadow values. |
| motion | `duration-fast`, `duration-base`, `easing-standard` | Indicative defaults when the design shows no motion. |
| size, layout | `size-control`, `size-touch-target`, `size-icon`, `layout-content-width`, `layout-form-width` | |

## Naming

`--<group>-<name>` in CSS, `group.name` in JSON. Lowercase, hyphenated, by role not by value: `--color-primary`, not `--green-500`. If the design file already has variables with sensible names, keep them.

The two files must contain the same set of names: CSS `--color-primary` ↔ JSON `color.primary`; CSS `--font-size-lg` ↔ JSON `font-size.lg`.

## Levels and sources

Every token gets a level (`fixed`, `indicative`, `tbd`) and a source. Defaults:

- From a brand guide or Figma variable: `fixed`.
- Exact color sampled with `palette.py` from the designer's own final design: `fixed`, source “sampled from <file>”. From a reference or someone else's product: `indicative`.
- Size, spacing or weight measured from a screenshot: `indicative`, with “measured from <file>” as source; divide by the scale factor first.
- Chosen by you to fill a gap: `indicative`, source “assumed”.
- Needed but genuinely unknown (licensed font not available, dark mode colors): `tbd`.

## tokens.css

```css
/* design-tokens/tokens.css — generated by design-to-dev. Levels: see tokens.json. */
:root {
  --color-primary: #2f6f4f; /* fixed · brand guide p.3 */
  --space-4: 16px;          /* indicative · measured */
}
```

## tokens.json (W3C Design Tokens format)

```json
{
  "color": {
    "primary": {
      "$value": "#2f6f4f",
      "$type": "color",
      "$description": "Main actions",
      "$extensions": { "design-to-dev": { "level": "fixed", "source": "brand guide p.3" } }
    }
  }
}
```

Types: `color`, `dimension`, `fontFamily`, `fontWeight`, `number` (line height), `shadow` (may be written as a CSS string), `duration`, `cubicBezier`. Tools such as Style Dictionary and Tokens Studio import this format.

Start from [../templates/tokens.css](../templates/tokens.css). Write the `level · source` comment on each line (a line without one inherits the line above), then generate tokens.json instead of writing it by hand:

```bash
python3 <skill-dir>/scripts/tokens_json.py <output>/design-tokens/tokens.css
```

It groups names by known prefixes (`color`, `font-size`, `space`, `radius`, `shadow`, `size`, `layout`, …) and records each level and source under `$extensions`.

## Summarize for the designer

After writing tokens, show a short table: the main colors, the type scale, and the count per level, plus anything you assumed. Designers spot a wrong color faster than a developer does.
