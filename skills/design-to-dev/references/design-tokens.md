# Design tokens

## What to extract

| Group | Tokens | Notes |
| --- | --- | --- |
| color | brand (primary, on-primary), neutrals (bg, surface, border, text, text-muted), feedback (success, warning, danger, info), state (primary-hover, primary-active, focus-ring, disabled-bg, disabled-text) | Derive hover/active by shifting lightness 6–10% when the design does not show them; mark derived ones Indicative. |
| font | family-base, family-display (if different), weight-regular/medium/bold | Use a system stack fallback after every family. |
| font-size + line-height | a scale such as xs, sm, md, lg, xl, 2xl | Snap screenshot measurements to the nearest step of a consistent scale (e.g. 12/14/16/20/24/32). |
| space | 1–8 steps on a 4px base | Measure padding and gaps; snap to the base. |
| radius | sm, md, lg, full | |
| shadow | sm, md, lg | Write as full CSS shadow values. |
| motion | duration-fast, duration-base, easing-standard | Only when the design or brand shows motion; otherwise Indicative defaults (120ms, 200ms, ease-out). |
| layout | content-max-width, breakpoint-md | |

## Naming

`--<group>-<name>` in CSS, `group.name` in JSON. Lowercase, hyphenated, by role not by value: `--color-primary`, not `--green-500`. If the design file already has variables with sensible names, keep them.

The two files must contain the same set of names: CSS `--color-primary` ↔ JSON `color.primary`; CSS `--font-size-lg` ↔ JSON `font-size.lg`.

## Levels and sources

Every token gets a level (`fixed`, `indicative`, `tbd`) and a source. Defaults:

- From a brand guide or Figma variable: `fixed`.
- Measured from a screenshot: `indicative`, with “measured from <file>” as source.
- Chosen by you to fill a gap: `indicative`, source “assumed”.
- Needed but genuinely unknown (licensed font not available, dark mode colors): `tbd`.

## tokens.css

```css
/* design-tokens/tokens.css — generated by design-to-dev. Levels: see tokens.json. */
:root {
  --color-primary: #2f6f4f; /* fixed · brand guide p.3 */
  --space-4: 16px;          /* indicative · measured */
}
```

## tokens.json (W3C Design Tokens format)

```json
{
  "color": {
    "primary": {
      "$value": "#2f6f4f",
      "$type": "color",
      "$description": "Main actions",
      "$extensions": { "design-to-dev": { "level": "fixed", "source": "brand guide p.3" } }
    }
  }
}
```

Types: `color`, `dimension`, `fontFamily`, `fontWeight`, `number` (line height), `shadow` (may be written as a CSS string), `duration`, `cubicBezier`. Tools such as Style Dictionary and Tokens Studio import this format.

Start from [../templates/tokens.css](../templates/tokens.css). Write the `level · source` comment on each line (a line without one inherits the line above), then generate tokens.json instead of writing it by hand:

```bash
python3 <skill-dir>/scripts/tokens_json.py <output>/design-tokens/tokens.css
```

It groups names by known prefixes (`color`, `font-size`, `space`, `radius`, `shadow`, `size`, `layout`, …) and records each level and source under `$extensions`.

## Summarize for the designer

After writing tokens, show a short table: the main colors, the type scale, and the count per level, plus anything you assumed. Designers spot a wrong color faster than a developer does.
